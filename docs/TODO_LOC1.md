# Первая локация: что осталось

Адреса — `original/install/game.exe`; дизассемблер: `.venv/bin/python tools/exe.py <адрес>`.

## Сделано

- **Квесты** — все действия из `location_1_quests.xml` (`web/src/quests.ts`):
  - `next_sub_quest` / `open_next_sub_quest` (0x5a8ac8, 0x5a8b89) — включить названную часть и выключить текущую.
    `open_` ещё ставит новой части флаг `+0x58`; чтение этого флага в exe не найдено, поэтому он не влияет на порт.
  - `disable_sub_quest` без имени — текущая часть (0x5a8a11).
  - `set_mark_if_mark` (0x481721). Метка `casual` / `hardcore` — сложность: exe при выборе сложности (0x44b2e0)
    снимает метку старой и ставит метку новой (имена — 0x426500). В порте метка берётся из `Game.difficulty`.
  - `store_state` / `restore_state` (0x47ef60 / 0x47f9e0): деньги, вода, уровни хранилищ, колодец, грядки, города и фермы.
    В снимок входят и ключ вредителей, ограничения магазина (грядки, бочки, ящики, покупка воды) и уровни статуй фермы (алтарь, рог, Нептун, сова, часы).
  - Журнал: `add_quest` (запись «локация/квест» у персонажа, заголовок `root/quests/<лок>/quests/<квест>/@header`),
    `add_task` (`item`, обычно `talk`), `add_task_count` (`item`, `count`), `remove_quest`, `remove_all_task`.
    exe читает только `item`: записи с `name=` (loc4, exams) пропускаются.
  - `add_weapon`, `add_owl`, `add_dragon_medal1/2` — сохраняются в игре; механика медалей дракона разобрана
    (0x481307/0x481400, см. «Не сделано»), у `add_weapon`/`add_owl` своей логики в exe нет.
- **Ручные сохранения** (`web/src/screens.ts` `saveLoadScreen`, `Game.save/load(slot)`, `Game.slotInfo`): экраны
  `save_game` (5 слотов 274×50 на 69; 109/160/216/266/315) и `load_game` (5 слотов на 69; 128/175/220/265/309 плюс
  автосохранение на 69; 94), фон `data/game/game_menu` 417×497 по центру, заголовок (79; 58) шрифтом
  stat_control_fonts_menu_normal, «Назад» (73; 397) 274×34. Строка занятого слота — `save_slot.sb`
  («%difficult%, День %game_day%») и время (`save_slot.text`), пустой — `empty_text` «---»; в load_game без единого
  сохранения — `no_slots`. Запись в занятый слот — `save_slot.confirm` «Перезаписать?», успех — «Игра успешно
  сохранена.»; загрузка из меню игры — `load_slot.confirm` «Ваша текущая игра будет потеряна. Продолжить?». Кнопки
  `game_menu`: save (101; 208), load (100; 250), quest (159; 290) 88×24 — журнал заданий открывается и из меню игры.
  В главном меню — «Загрузить» (main_menu/load 193; 400) и четвёртая кнопка «Загрузить» в new_or_continue_game
  (310; 210). Слоты — localStorage `iris-flower-save-v3:<игрок>:slot<N>` со штампом `savedAt`; автосейв по-прежнему
  в `iris-flower-save-v3:<игрок>` и пишется сам (persist при уходе/скрытии вкладки, как раньше).
- **Окно заданий** (`web/src/questscreen.ts`, exe 0x57cb40): портрет `miniimages/<персонаж>`, значки `miniimages/need/<предмет>`,
  счётчик «есть/нужно» (белым, выполнено — зелёным), по 5 в ряд, со 6-го — новая строка на высоту портрета + 0x14.
  Отступ между записями журнала — допущение.
- **Ключи волн** (`set_pests_key`, выбор волны 0x41c400, `BugArriver.pick`): играют только волны с ключом, равным
  ключу вредителей фермы (по умолчанию ""). За последней волной — переход на `wave_loop`; при пропуске волн с чужим
  ключом за концом — на `wave_loop − 1` (ключ пустой) или на 0 (ключ задан).

- **Длина дня** (`Game.dayCur / dayNext`, у каждой фермы своя): поля фермы `+0x4c` (запас) и `+0x50` (остаток дня,
  день кончается при 0 — 0x42fc90). При загрузке оба = `min_time` (0x42ace3); когда день кончился (0x51dad8 → 0x42f1f0),
  остаток = запас, запас += `inc_time`, но не больше `max_time`. Итог для loc1: 35, 35, 36 … 50 с. Атрибут `time` exe
  перезаписывает (`min_time` читается следом), без `min/max/inc` день постоянный.

- **Уровни колодца** (`web/src/well.ts`): уровень — поле фермы `+0x7f0`, 0 — нет колодца, покупка (0x4333d0) ставит новый
  колодец и прибавляет 1. Первый — базовый `well` / `pail` (метка `shop_well`: 10-й день или квест). Улучшения (0x4f32e0):
  на уровне L предлагается `well_object[well_<L+1>]` (0x4f2290, 0x4f2400); флаг (0x4f2ea0) — метка `shop_well_<L+1>`
  (метки `shop_well_1…3` ставит сам конструктор GameHolder, 0x44a0cc) и разрешение `+0x82c` (квест `enable_buy_well`).
  Нет ключа — последний уровень. Итог во всех локациях: базовый → `well_2` → `well_3` (loc1: `well_00` → `well_02` →
  `well_03`; `well_01` из ключа `well_1` не используется — у него нет картинки и ведра в resource.xml).
  Картинки — по resource.xml: `root/obstacles/<колодец>` (loc1: `well_02` → картинка `well_01`, `well_03` → `well_02`;
  у loc2–5 — `empty`) и «ведро» `root/<ведро>/pail|water|mask` (у loc2–5 это и есть фонтан, родник, акведук, статуя;
  у каждого уровня своя картинка), место ведра — `game_screen/well_ctrl/<ведро>`.
  `add_well` / `remove_well` (квесты loc2–4) — см. «Перестройка фермы квестами» ниже.

- **Букеты** (`Game.fillOrders`, `nextOrderItems`, `randomBouquet`): заказы — 4 места; пустые заполняются при открытии
  экрана букетов (0x433fc0), место проданного — сразу (0x434050). Следующий заказ (0x434270): `bouquet_set` по порядку
  (читаются первые `bouquet_count` записей — в loc1 их 0), потом случайный; не собрался — номер `bouquet_set` = длина / 2.
  Случайный (0x434580): кандидаты — цветы `products`, которые есть на складе; запись — последняя с `day` ≤ дня;
  r = rand · (p3 + p4 + p5): r ≤ p3 — 3 цветка, r ≤ p3 + p4 — 4, иначе 5; цветы — по весам `p_<цветок>`. Нет кандидатов —
  заказ не создаётся; у проданного места старый букет остаётся (0x434270 при неудаче слот не трогает), пустых конусов нет. Цена (0x4d1d5d) × `price_k` размера (1.15 / 1.25), большой кулёк `big-flowers` со сдвигом −20; 0.
  Проверено прогоном: размеры 71 / 22 / 7 %, цены 3/4/5 ромашек — 12 / 18 / 25.

- **Мудрая сова** (`web/src/owl.ts`, данные `root/shop/location_1/owl`): уровень — поле совы `+0x24`, 0 — нет.
  Состояния (0x5002f0): покой rand(min_stand..max_stand) → активна rand(min_active..max_active) (горят глаза) → покой.
  Нажатие в активности (0x501580) — анимация action, по её концу — покой; опыт (0x569750) = ⌊exp · остаток / длина
  активности⌋ + 1 («+N Опыт»). Купить уровень (0x4fe0c0) — уровень < count и метка `shop_owl_<уровень+1>`; видна, если
  уровень > 0 или её можно купить (0x4fe260). `shop_owl_1/2` — день 0 (метки по дням ставятся при «день ≥», 0x499610),
  `shop_owl_3` — квест magic_statue, он же даёт `add_owl` (бесплатно +1 уровень, 0x433670). Цены 0 / 100 / 200,
  опыт 10 / 15 / 20. Частиц `root/particles/owl` в resource.xml нет. **Допущение**: сова живёт только днём.
- **Статуи остальных ферм** (`web/src/statue.ts`, общий класс exe 0x4fa680 / 0x4fb590 / 0x4fcad0, эффект — виртуальный
  метод +0x20 вида): цикл как у совы, но после нажатия в покой — на следующем кадре (проверка конца анимации обратная).
  Покупка — метки `shop_<вид>_<уровень+1>`, квест `add_<вид>` даёт бесплатный уровень (loc2 Нептун, loc3 алтарь,
  loc4 горн, loc5 часы).
  - **Нептун** (0x503b00): урон rand(min_damage..max_damage) каждому вредителю, но не насмерть — жизнь не ниже 0.1;
    `prize_k` прибавляется к множителю приза вредителя (+0x100).
  - **Часы** (0x505730, 0x5057d0): замедление `slow_k` вредителей (поле фермы +0x834) на `max_activete_time` секунд,
    снимается и в начале / конце дня. Замедляются анимации и укусы вредителей (0x40f4c8, 0x58e8d0); в порте — весь их
    кадр (dt · slow), день идёт как обычно. `min/max_damage` у часов в данных есть, но эффект их не читает.
  - **Алтарь** (0x4fe7d0): случайный приз из `items` в `position` + случайный сдвиг в пределах `drop_offset`.
  - **Горн** (0x504bc0, 0x504650): round(rand(min_bugs..max_bugs)) вредителей из `bugs` по одному в секунду (первый
    сразу), у каждого множитель приза + `prize_k` горна.

- **Призы из вредителей** (`web/src/prizes.ts`, данные `root/dropped_items`, `farm/prizes_set`):
  - выбор (0x431e40): вес ступени — `prize_k` · множитель вредителя (у пустой ступени — просто `prize_k`), r = rand · сумма;
    из призов ступени — случайный, без тех, чья `difficults` не содержит сложность. У вредителя с `$N` — N гарантированных
    призов из всех ступеней (0x410300). Проверено прогоном: «ничего» 21.4 % при множителе 1 (ожидание 21.7 %).
  - сбор нажатием (0x430370, попадание по пикселям 0x4b54d0): «exp» — опыт, «gold» — золото (в loc5 надпись про
    кристаллы), «water» — вода сколько влезет (0x566a80); надпись «+N …» цветом `float_string_color`. Лежат до конца дня.
  - **Реализовано**: место — первая свободная клетка сетки в радиусе 3 от точки вредителя (`cellNear`, 0x428870); прежнее приближение (случайный сдвиг до клетки) убрано.
    сбор — к счётчику панели летит эмиттер частиц `effect` с картинкой приза (`data/particles/prizes/<имя>`) за `effects/prizes time` 0,6 с; так же плод при сборе (`effects/product`, `particles/products`). Движок частиц перенесён целиком (см. «Particle engine» ниже), полёт — через `ParticleLayer.fly`.
    В exe (0x427930) предмет невидим: каждый кадр тикает эмиттер реальным dt (0x42795f), сам движется по пути (0x46aab0) и
    ставит эмиттер в свою точку (0x79f2b0) — частицы спавнятся на отрезке «предыдущая точка → текущая». По имени предмета
    (`product` / `water` / `prizes`, 0x413610) масштаб или гравитация частиц умножаются на оставшееся время: product —
    scale = сохранённый · остаток, prizes — то же + 0,4 (0x880b40), water — гравитация (макс) = остаток.
- **Модификаторы вредителей** (`parseBugSpec`, разбор 0x401fa0, применение 0x40e0a0): после «!» — `@N` уровень (без него
  модификаторы не действуют), `*k` жизнь, `#k` скорость, `$N` гарантированные призы, `+k` атака; опыт = ⌊опыт · (1 + * / 3
  + # / 3)⌋. Картинка уровня `@` (0x402040): имя `root/aura/aura_N`, параметры — properties.xml `<aura><aura_N>`:
  image `data/bugs/aura/aura_N`, offset «−45;−20» (левый верх кадра относительно точки вредителя, exe +0x80/+0x84),
  play_time 1, rows 12 — полоса из 12 кадров 90×80, играет по кругу (ролик живёт на вредителе, поле +0x1fc).
  Флаг «!» (0x4197a0 ищет символ в строке и стирает её часть после «!», сеттер 0x410560 → поле +0x8b, конструктор
  обнуляет): такой вредитель не замирает на время анимации удара — в exe тик поведения 0x58e8d0 (движение, укусы,
  звуки) пропускается, только пока играет анимация удара (флаг +0x88: тик после удара переносит +0x89, 0x410324
  ставит его в hit, снимается по концу анимации 0x40fbde); у «!»-вредителя поведение продолжается, а анимация удара
  идёт отдельными роликами (список +0x174, проигрываются все 0x410300). В порте: playHitOverlay поверх спрайта.

## Particle engine (web/src/particles.ts)

Движок перенесён целиком по exe (адреса — game.exe; в `tools/export_particles.py` старые адреса — от exe первой «Фермы»):

- **Эмиттер** — конфиг .psi (+0x00…+0x7c) + состояние: загрузчик 0x79f760 читает 128 байт и делит
  speed/gravity/radial/tangential на 100 (0x888a80 — именно деление, не умножение); создание 0x7e34c0 (максимум 100
  эмиттеров на систему, 0xa4d8 байт, 500 частиц по 0x54); такт 0x79eb00; тикер 0x79ea40 (период +0x84 = 1/частота,
  у всех эмиттеров игры 0 — такт каждым вызовом); `setPos` 0x79f2b0 (отрезок «предыдущая → текущая точка», с флагом —
  сдвиг частиц); старт 0x79f430 (duration −1 → elapsed −1 и время не тикает, иначе 0); стоп 0x79f480 (elapsed −2).
- **Такт 0x79eb00**: elapsed ≥ 0 → += dt, досчитал duration → −2; частицы: возраст, смерть перестановкой с последней
  (0x80dab0), скорость += (нормаль от эмиттера · radial + перпендикуляр (−y, x) · tangential) · dt, vy += gravity·dt,
  позиция += скорость (без dt), spin/scale/цвет += свои производные·dt; нормаль — через быстрый обратный корень
  0x7e4150 (трюк Quake, 0x5f3759df, множители 0,4999/1,5). Эмиссия: rate·dt с накоплением дробной части, округление
  к нулю (управляющее слово 0xc00); спавн — позиция на отрезке эмиттера (rand 0…1) + разброс ±2 (0x8ac8ac/b8),
  направление angle − π/2 + rand(0, spread) − spread/2, с флагом `relative` — ещё угол отрезка эмиттера назад
  (0x7e4190 → atan2); жизнь/скорость/гравитация/radial/tangential — rand(от…до), масштаб/spin/цвет — rand(от…до
  от+(до−от)·разброс), производные = (до − значение)/жизнь.
- **Список эмиттеров** 0x7e32a0/0x7e3340: t += dt (не больше 1 с), каждый шаг 0,01 с (0x8af1c0) — тик всех эмиттеров
  с dt = 0,01; закончившие (elapsed −2 и без частиц) удаляются. Поэтому скорости — пиксели за такт 0,01 с.
- **Отрисовка** 0x79f4c0: поворот = spin·возраст, масштаб по обеим осям, цвет trunc(канал·255) (0x79fcd0, 0x8808e8),
  позиция + смещения эмиттера (+0xa4/+0xa8 — нули); смешивание — режим 0 (флаг +0x80 у psi-эмиттеров всегда 0),
  как у обычных спрайтов.
- **Полёт к панели** 0x426e90/0x427530/0x427780/0x427930 — см. «Призы из вредителей»; картинка частиц — ресурс
  `combine(part_path, имя приза)` из `<effects>/<эффект>/part_path` (properties_ru.xml), эмиттер — `<particles psi>`.
  Путь 0x46a790: точки A@0, M@T/2, B@T, M = середина + (−k, +k), k = `interpolator_k` (prizes 75, product 85,
  water 90); касательные нулевые (0x46a630 ставит (0,0) с флагами startSet/endSet, tension/continuity/bias сегмента
  из 0x46ae80 = 0), интерполяция 0x46aff0 — Эрмит, на участке это гладстеп 3u²−2u³. Формулы касательных середины
  (0x46b4d0, Коханек–Бартелс) выписаны в комментарии `FlightPath`.

- **Серии ударов** (`Farm.comboHit`, `Bug.setComboTarget`, exe 0x430370, 0x410070): попал по вредителю (и по его мишени,
  если она есть) — счётчик фермы + 1 (+0x708), на вредителе новая мишень `bugs/target` в случайной точке
  rand % (2·click_radius − 25) от угла зоны нажатия; попадание в мишень — квадрат 25 × 25 от её угла. Множитель урона —
  `damage` последней строки `combo_set` с ударом подряд ≥ `comobos_count` (×1.2 с 3-го … ×2.75 с 17-го). Мимо мишени —
  серия 0, мишень пропадает. `combo_time` (+0x704) exe только отсчитывает, серию не сбрасывает; сбрасывает начало дня.
  Надпись — слушатель HintLayer `0x565410` (вызов через `0x45e1c0` с vtable `+0x50`): только с 3-го удара, шрифт
  `root/bonus_events_white/font`, цвет RGB(232,102,102), одна строка по центру вредителя (точка `bug+0x98`, у краёв
  прижимается `0x563ed0`). «Комбо N» всегда; « Урон xM» приписывается через пробел, только если множитель изменился
  с прошлого показа (HintLayer `+0x124`) и не равен 1,0. Серия мимо мишени сбрасывается, но запомненный множитель — нет.

- **Автосборка букетов** (`web/src/autobouquet.ts`, экран букетов): счётчик фермы (+0x770) — проданные в букетах цветы
  (+ число цветов букета, 0x434078). Пороги `levels_array` идут подряд (80, затем ещё 100; 0x4093f0). Уровень 1 —
  нажатие на свободное место букета переносит туда нужный цветок из корзины (0x510b80); уровень 2 — то же, а если не
  вышло, букет заполняется всем, что есть (0x510da0). Полоса `control` (151; 511): картинка прогресса, обрезанная по доле
  (0x5587a0), значок уровня, на последнем уровне — `complete`; подсказка `tooltips/auto_bouquet_<уровень>` и «нужно
  продать %count%» (0x558250). Цветок при автопереносе летит по прямой за 0,25 с (0x511060: t = progress/0,25 —
  константа 0x888744, кламп ≤ 1 сравнением с qword 1.0 (0x880178), позиция = старт + (цель − старт)·t — линейный
  lerp, 0x43ec20/0x4645b0/0x4649a0; дуги и сглаживания нет).

## Пятая локация

Панель `stat_control_loc5` с «Кристаллами» вместо «Монет» (`stats/crystals_title`, надпись сжимается по доске) и фон экрана
букетов `bouquets_back_loc5`; приз-валюта уже назывался кристаллами. Окно покупки воды в 5-й локации — тексты `buy_water_loc5`
выгружены, но денег в окне не показывает (у обычного тоже). Картинка кристалла на панели — в самой `stat_control_loc5`.

## Дерево-идол (5-я локация)

`farm/marks_obstacle`: картинка `data/Tree/idol-tree-00…05` 400×150 в (235; 47), по метке `treemark_N`; квесты ставят `treemark_2…6`
(`set_mark`) и `add_vegetation` веток (`blue/green/red/yellow_branch_1`). Показывается картинка последней поставленной метки, она же
препятствие для вредителей и Робина. **Допущение**: `treemark_1` в квестах не ставится — пока ни одной метки нет, виден росток
(`idol-tree-00`). Ветки (`*_branch_N`, картинка `empty`), `idol_tree_flowers` и растение `idol_tree` (жажды нет, плод `p_idol_tree`
15000) — частично. Сделано: грядки с `veg_name` стоят с начала игры (`ridge_10` — дерево-идол, 6–9 — ветки `red/blue/yellow/green_branch_1`,
грядка без картинки `plain`: игрок на неё ничего не сажает, не продаёт и не улучшает); `add_vegetation *_branch_1` сажает ветку на
её грядку; `remove_all_vegetations` их не трогает. Растения идола и веток, плоды `p_*_fruit_N` / `p_idol_tree` и картинки выгружены.
Ветка стадии N считается предметом квеста (`have_items name="green_branch_3"`, окно заданий): считаются растения этого имени на грядках фермы.
Не сделано: Картинка `tree/idol_tree_flowers` в данных игры не упоминается (ни в XML, ни в exe) — в порте не используется. Особенности `idol_tree` (плод за 15000) — как у обычного растения.

## Перестройка фермы квестами (локации 2–4)

Действия этапов квестов (`store_state` → …), раньше пропускавшиеся: `set_barrels` / `set_boxes` (число уровней), `set_max_barrels` /
`set_max_boxes` (докупать можно только до этого числа), `remove_well` (без `count` — колодца нет, иначе минус столько уровней) /
`add_well` (+1 уровень), `enable_buy_water` (кнопка «Купить воду»), `enable_manual_work` (false — игрок не поливает и не собирает,
только Робин; экзамен в 3-й локации), `set_ridges` (`installed` грядок осталось: из начальных `ridgeCap`, остальное — купленные; докупить
ещё `not_installed`), `update_quest_title` / `change_quest_person` (запись журнала), `add_dragon_medal3` (награда ступени 3).
**Проверено по данным**: `set_ridges` задаёт число оставшихся начальных грядок и сколько ещё можно докупить; `enable_manual_work=false` отключает
полив/сбор игроком (экзамен в 3-й локации); `reset_bug_item` обнуляет предмет вредителей перед новой выдачей. В exe эти действия
(0x4837bb…) не читались, но данные квестов подтверждают эту семантику.

## Сложность

Экран выбора (`select_difficult_screen`: «Легкий» / «Сложный» и флажок туториала) перед комиксом новой игры;
значения `difficult` (exe 0x425c90, getters 0x4263b0…0x4264b0): покупка ×`buy_price` (0x4b5fb8: цена × умение × k + 0,5 → целое),
продажа ×`sell_price` (0x4b6058), жизнь вредителя ×`bug_life` (0x40eb60), пороги `exp_levels` ×`exp_k` (0x428070; не опыт за действия,
как гласила таблица в DIFF_FROM_MF1), `pour_count` = 1 в обеих и нигде не нужен; призы по `difficults`; раздельные таблицы рекордов.
**Приставки волн разобраны** (exe 0x419650, вызывается перед спавном каждой записи волны и горна): на сложном подходят
все строки; на лёгком — все, кроме начинающихся с точного «hardcore-» (строки без «-» годны для любой сложности).
0x419650 только фильтрует и не снимает приставку. В спавне
(0x41bad0): 0x4197a0 стирает из рабочей копии всё от `!` до конца и возвращает флаг «!», 0x419650 фильтрует,
затем в создание вредителя уходит строка без `!`-части, но с приставкой `casual-`/`hardcore-`; чистое имя
срезается позже, в загрузчике определения 0x40e2a0 — всё до первого '-' (см. «Допущения» → «Приставка»).
В порте экспортёр отдаёт `specs[].name`/`bugs` без приставки и модификаторов —
рантайм ищет определение по чистому имени, поведение совпадает с данными.
**Допущения**: стандартная таблица рекордов одна на обе сложности.
Жажда Робина (разобрана по exe): срок — случайное целое `round(hunger_min)`…`round(hunger_max)` секунд (0x4c87b0), на **лёгком ×10**
(250–350 с — дольше дня, поэтому там почти не бывает), на сложном как есть (25–35 с). Заводится в начале дня (0x4c75a0) и когда
Робина напоили. Хочет пить, когда осталось меньше половины срока (0x4c7670, флаг +0xe1; ряд капель `progresses/helper_hunger`,
картинка `drop_helper`), на нуле улетает до конца дня (+0xe2). Нажатие по жаждущему Робину (0x430370: попадание по `click_radius`,
0x4c8000) поит его: расходуется вода, срок заводится заново (0x4c80b0); воды нет — событие «нет воды». Нажатие по нежаждущему Робину (0x4c7fa0 → 0x4c8020, звук `helper_click`) — ускорение: 5 с (0x4c8130) скорость полёта растёт на 0,5 к множителю
задачи (0x4c7870) и удар вдвое сильнее (0x4c7d10 — поле +0xa0 это `attack`); снова нажать можно через 15 с после прошлого нажатия.
**Допущение**: в начале дня счётчик на нуле — первые 5 с Робин ускорен, нажимать можно с 15-й секунды (как заводятся счётчики 0x4cb920, не ясно).
Проверено по данным: квесты `*_hardcore` (`detective_arrive_hardcore`, `explorer_returns_hardcore`, `hardcore_quest`) используют только уже реализованные действия
(`have_mark`, `quest_status`, `add_quest`, `add_task_count`, `remove_items`, `set_mark`, `set_quest_status`, `next_sub_quest`, `change_quest_person`)
и метки `casual` / `hardcore`; отдельных действий со статуями/наградами в них нет. Прохождение живым игроком не проверялось.

## Окно умений (level_up)

Проверено по exe/XML (конструктор экрана 0x516ef0, виджет описания 0x7c1390, текст читается из узла
`/description` — 0x7c0d90 берёт только `font`/`color`; `position`/`dimensions` — атрибуты базового виджета):
узел `<description>` — позиция (98; 301), размер 220×85, шрифт `root/font/stat_control_1`, цвет 210;210;210.
В порте (`web/src/levelup.ts`): текст на (98;301), перенос по 220, при высоте > 85 масштабируется
вниз до `max(0.5, 85/textHeight)`, чтобы уместиться на доске. Левый край доски на фоне перекрыт рисунком
листа (`level_up_back`) — текст стоит в тех же координатах поверх того же фона, как в оригинале; точная
визуальная вёрстка (переносы строк движка) проверкой живым игроком не подтверждена.

Стручок умений — виджет прогресса (конструктор 0x57a450, vtable 0x88f7e4, отрисовка 0x57b840), один на
каждый узел `root/level_up/progresses/<умение>` (создаётся 0x576df0, имя — аргумент; `helper` в имени даёт
инверсную полосу `bob_prog_inv`, 0x5770f1). Доля приходит через свойство статистики (0x5773f0 → 0x577530:
`fld [стат + 0x64]` → 0x57b6a0) — доля уровня; писатель дроби в объекте статистики не прослежен, но
семантика однозначна: 0 — пустой стручок, максимум — полный.

- **Кадр**: `setValue` (0x57b760/0x57b6a0) ищет позицию ролика: `elapsed = play_time/rows · trunc(rows·доля + 0,5)`;
  кадр = `clamp(elapsed / (play_time·1000/rows), 0, rows−1)` (геттер 0x791be0, кламп 0x4769c0), то есть
  `trunc(10·доля + 0,5)` по 10 кадрам `bob_prog`. Ролик (TextureAnimationController, 0x790ed0) никогда
  не тикает — обёртка тика 0x792110 не вызывается, поэтому кадр статичен, а флаг цикла (+0x2f = 1)
  не играет роли.
- **Обрезка**: отрисовка 0x57b840 рисует полосу усечённой по горизонтали — `trunc(100·доля + 0,5)` px кадра
  в `anim_pos` от бара (у artist-кадров доля уже заложена в ширину, обрезка почти всегда не видна).
- **bob_prog_sel не рисуется**: поле `+0x8c` всегда 1 (0x57a6ad), ветка с роликами (0x57b990) не выполняется;
  выбор умения в exe обозначается только рамками `selected`/`overed` (0x577290). В порте убран
  подсвеченный стручок выбранного умения.
- **Мусор в данных**: `root/progress/bob_progress` (99×1014) в exe не упоминается (строки нет) — мёртвые
  данные, как `trophy_room_rect`; `glass.png` (22×6) грузится конструктором (0x57a4b5) и рисуется поверх
  (0x57ba3a) в позиции узла `<progress>`, а эти позиции в данных выглядят мусорными (`trade`: −278;−230) —
  в порте не рисуется.

### Допущения (не блокируют, требуют точечного разбора exe/проверки)
- **Приставка имени вредителя — разобрано**: спавн 0x41bad0 хранит спецификацию целиком (после 0x4197a0, стирающего
  «!» с хвостом, и фильтра 0x419650), 0x430020 → 0x40dc60 кладёт её в поле +8 вредителя как есть; срез происходит
  позже, в загрузчике определения 0x40e2a0 (вызывается из 0x40e070 сразу после создания): `idx = имя.find('-')`,
  если найден — `erase(0, idx + 1)` (0x410f70/0x402fb0 на 0x40e370–0x40e3a3), затем 0x40e460 строит путь
  `root/bugs/<имя>` и читает определение. Срезается всё до первого '-', а не только приставки сложностей:
  «hardocre-» опечатка срезается так же; имена типов в `<bugs>` данных без '-' (`boar`…`snail_no_armour`),
  поэтому на данных эквивалентно прежнему правилу порта. Порт приведён к точному правилу (`parseBugSpec`).
- **Квесты**: закрыто — exe в `add_quest` (0x482a8a–0x482e99) читает только `quest_name`/`person`/`location`;
  атрибут `item` читают лишь `add_task` (0x4832a4, push 0x8826ac) и `add_task_count` (0x4830ae, push 0x882674),
  а в данных `add_quest` с `item` не встречается вовсе. Отдельное действие `add_quest_location` (0x482e99)
  в данных тоже не используется. Медали дракона разобраны
  (0x481307/0x481400): берётся медаль `dragon_medal` (0x4f58e0), medal1 награждает только если уровня ещё нет
  (`ja` после 0x4f6a70), medal2 — только пока уровень ≤ 1 (`cmp 1; ja`); 0x44b040 кладёт медаль в список +0x1d8,
  ступень растёт отдельно (0x4f6a50), уровень 3 у dragon_medal — конструктор 0x4f58f0. Порт совпадает:
  medal1 → ступень 1, medal2 → следующая ступень (до 3).
- **Мелочи**: отступ записей журнала — высота элемента списка в exe не разобрана (`web/src/questscreen.ts`);
  фон окна покупки воды — «резина» `rubber_back` растянута на окно (`web/src/farm.ts`); стандартная таблица
  рекордов одна на обе сложности — не подтверждено отдельно. (**допущения**)
- Проверка прохождением живым игроком (в т.ч. квесты `*_hardcore`, ветки сложности).
