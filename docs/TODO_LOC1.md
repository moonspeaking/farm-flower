# Первая локация: что осталось

Адреса — `original/install/game.exe`; дизассемблер: `.venv/bin/python tools/exe.py <адрес>`.

## Сделано

- **Квесты** — все действия из `location_1_quests.xml` (`web/src/quests.ts`):
  - `next_sub_quest` / `open_next_sub_quest` (0x5a8ac8, 0x5a8b89) — включить названную часть и выключить текущую.
    `open_` ещё ставит новой части флаг `+0x58`; где он читается, не найдено.
  - `disable_sub_quest` без имени — текущая часть (0x5a8a11).
  - `set_mark_if_mark` (0x481721). Метка `casual` / `hardcore` — сложность: exe при выборе сложности (0x44b2e0)
    снимает метку старой и ставит метку новой (имена — 0x426500). Выбора сложности нет, игра идёт как casual.
  - `store_state` / `restore_state` (0x47ef60 / 0x47f9e0): деньги, вода, уровни хранилищ, колодец, грядки, города и фермы.
    В exe снимок шире: ещё ключ вредителей и уровни предметов фермы (алтарь, рог, Нептун, сова, часы) — их в порте нет.
  - Журнал: `add_quest` (запись «локация/квест» у персонажа, заголовок `root/quests/<лок>/quests/<квест>/@header`),
    `add_task` (`item`, обычно `talk`), `add_task_count` (`item`, `count`), `remove_quest`, `remove_all_task`.
    exe читает только `item`: записи с `name=` (loc4, exams) пропускаются.
  - `add_weapon`, `add_owl`, `add_dragon_medal1/2` — сохраняются в игре, своих механик пока нет.
- **Окно заданий** (`web/src/questscreen.ts`, exe 0x57cb40): портрет `miniimages/<персонаж>`, значки `miniimages/need/<предмет>`,
  счётчик «есть/нужно» (белым, выполнено — зелёным), по 5 в ряд, со 6-го — новая строка на высоту портрета + 0x14.
  Отступ между записями журнала — допущение.
- **Ключи волн** (`set_pests_key`, выбор волны 0x41c400, `BugArriver.pick`): играют только волны с ключом, равным
  ключу вредителей фермы (по умолчанию ""). За последней волной — переход на `wave_loop`; при пропуске волн с чужим
  ключом за концом — на `wave_loop − 1` (ключ пустой) или на 0 (ключ задан).

## Не сделано

### Колодец: уровни
Разобрано:
- `well_object` фермы: ключ атрибута для уровня `n` — `well` / `pail` при `n = 0`, иначе `well_<n>` / `pail_<n>` (0x4f2290, 0x4f2400).
  Если атрибута нет — берётся предыдущий (0x4f3514…, вызов 0x4d7130). В loc1 `pail_1` нет, `pail_2` записан дважды.
- Свойства уровня — `items/wells/<имя>` (price, delay, fill_time, water_capacity, pail, pail_height), загрузка 0x4c0710.
- Номер уровня — поле фермы `+0x7f0` (0x42f1b0). Показ: `n = уровень + флаг`, флаг (0x4f2ea0) = есть метка
  `shop_well` (уровень 0) или `shop_well_<уровень+1>` **и** условие фермы 0x433ec0.
- Метка `shop_well` ставится на 10-й день (`set_mark_by_day`) и квестом; `shop_well_2`, `shop_well_3` в данных не ставятся нигде.

Не разобрано: что проверяет 0x433ec0, когда растёт `+0x7f0` (покупка в магазине), почему уровни 2–3 недоступны по меткам.

### Длина дня
`farm time / min_time / max_time / inc_time` (loc1: 40 / 35 / 50 / 1). Порт берёт `time`. Формулу роста нужно найти в exe.

### Размер букетов
`bouquet_random_set` с вероятностями `p_size3 / p_size4 / p_size5` (loc1: 1.0 / 0.3 / 0.1) — порт их не читает;
картинки больших букетов (`big-flowers`) нет.

### Сова (`owl`) в магазине
`shop buy items="…; owl"`, метки `shop_owl`, `shop_owl_1`, `shop_owl_2` (день 0). Механика — по exe.

### Волны: модификаторы и сложность
Записи вида `snail!@1*2$2`, приставки `casual-` / `hardcore-`; смысл модификаторов не разобран.

### Прочее
- Серии ударов (`combo_set`), призы из вредителей (`dropped_items`), автосборка букетов (`auto_bouquet_level`).
- Комната трофеев (медали дракона).
- Описание умения вылезает за доску в окне умений.
