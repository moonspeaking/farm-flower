# Первая локация: что осталось

Адреса — `original/install/game.exe`; дизассемблер: `.venv/bin/python tools/exe.py <адрес>`.

## Сделано

- **Квесты** — все действия из `location_1_quests.xml` (`web/src/quests.ts`):
  - `next_sub_quest` / `open_next_sub_quest` (0x5a8ac8, 0x5a8b89) — включить названную часть и выключить текущую.
    `open_` ещё ставит новой части флаг `+0x58`; где он читается, не найдено.
  - `disable_sub_quest` без имени — текущая часть (0x5a8a11).
  - `set_mark_if_mark` (0x481721). Метка `casual` / `hardcore` — сложность: exe при выборе сложности (0x44b2e0)
    снимает метку старой и ставит метку новой (имена — 0x426500). В порте метка берётся из `Game.difficulty`.
  - `store_state` / `restore_state` (0x47ef60 / 0x47f9e0): деньги, вода, уровни хранилищ, колодец, грядки, города и фермы.
    В снимок входят и ключ вредителей, ограничения магазина (грядки, бочки, ящики, покупка воды) и уровни статуй фермы (алтарь, рог, Нептун, сова, часы).
  - Журнал: `add_quest` (запись «локация/квест» у персонажа, заголовок `root/quests/<лок>/quests/<квест>/@header`),
    `add_task` (`item`, обычно `talk`), `add_task_count` (`item`, `count`), `remove_quest`, `remove_all_task`.
    exe читает только `item`: записи с `name=` (loc4, exams) пропускаются.
  - `add_weapon`, `add_owl`, `add_dragon_medal1/2` — сохраняются в игре, своих механик пока нет.
- **Окно заданий** (`web/src/questscreen.ts`, exe 0x57cb40): портрет `miniimages/<персонаж>`, значки `miniimages/need/<предмет>`,
  счётчик «есть/нужно» (белым, выполнено — зелёным), по 5 в ряд, со 6-го — новая строка на высоту портрета + 0x14.
  Отступ между записями журнала — допущение.
- **Ключи волн** (`set_pests_key`, выбор волны 0x41c400, `BugArriver.pick`): играют только волны с ключом, равным
  ключу вредителей фермы (по умолчанию ""). За последней волной — переход на `wave_loop`; при пропуске волн с чужим
  ключом за концом — на `wave_loop − 1` (ключ пустой) или на 0 (ключ задан).

- **Длина дня** (`Game.dayCur / dayNext`, у каждой фермы своя): поля фермы `+0x4c` (запас) и `+0x50` (остаток дня,
  день кончается при 0 — 0x42fc90). При загрузке оба = `min_time` (0x42ace3); когда день кончился (0x51dad8 → 0x42f1f0),
  остаток = запас, запас += `inc_time`, но не больше `max_time`. Итог для loc1: 35, 35, 36 … 50 с. Атрибут `time` exe
  перезаписывает (`min_time` читается следом), без `min/max/inc` день постоянный.

- **Уровни колодца** (`web/src/well.ts`): уровень — поле фермы `+0x7f0`, 0 — нет колодца, покупка (0x4333d0) ставит новый
  колодец и прибавляет 1. Первый — базовый `well` / `pail` (метка `shop_well`: 10-й день или квест). Улучшения (0x4f32e0):
  на уровне L предлагается `well_object[well_<L+1>]` (0x4f2290, 0x4f2400); флаг (0x4f2ea0) — метка `shop_well_<L+1>`
  (метки `shop_well_1…3` ставит сам конструктор GameHolder, 0x44a0cc) и разрешение `+0x82c` (квест `enable_buy_well`).
  Нет ключа — последний уровень. Итог во всех локациях: базовый → `well_2` → `well_3` (loc1: `well_00` → `well_02` →
  `well_03`; `well_01` из ключа `well_1` не используется — у него нет картинки и ведра в resource.xml).
  Картинки — по resource.xml: `root/obstacles/<колодец>` (loc1: `well_02` → картинка `well_01`, `well_03` → `well_02`;
  у loc2–5 — `empty`) и «ведро» `root/<ведро>/pail|water|mask` (у loc2–5 это и есть фонтан, родник, акведук, статуя;
  у каждого уровня своя картинка), место ведра — `game_screen/well_ctrl/<ведро>`.
  `add_well` / `remove_well` (квесты loc2–4) — см. «Перестройка фермы квестами» ниже.

- **Букеты** (`Game.fillOrders`, `nextOrderItems`, `randomBouquet`): заказы — 4 места; пустые заполняются при открытии
  экрана букетов (0x433fc0), место проданного — сразу (0x434050). Следующий заказ (0x434270): `bouquet_set` по порядку
  (читаются первые `bouquet_count` записей — в loc1 их 0), потом случайный; не собрался — номер `bouquet_set` = длина / 2.
  Случайный (0x434580): кандидаты — цветы `products`, которые есть на складе; запись — последняя с `day` ≤ дня;
  r = rand · (p3 + p4 + p5): r ≤ p3 — 3 цветка, r ≤ p3 + p4 — 4, иначе 5; цветы — по весам `p_<цветок>`. Нет кандидатов —
  место пустое. Цена (0x4d1d5d) × `price_k` размера (1.15 / 1.25), большой кулёк `big-flowers` со сдвигом −20; 0.
  Проверено прогоном: размеры 71 / 22 / 7 %, цены 3/4/5 ромашек — 12 / 18 / 25.

- **Мудрая сова** (`web/src/owl.ts`, данные `root/shop/location_1/owl`): уровень — поле совы `+0x24`, 0 — нет.
  Состояния (0x5002f0): покой rand(min_stand..max_stand) → активна rand(min_active..max_active) (горят глаза) → покой.
  Нажатие в активности (0x501580) — анимация action, по её концу — покой; опыт (0x569750) = ⌊exp · остаток / длина
  активности⌋ + 1 («+N Опыт»). Купить уровень (0x4fe0c0) — уровень < count и метка `shop_owl_<уровень+1>`; видна, если
  уровень > 0 или её можно купить (0x4fe260). `shop_owl_1/2` — день 0 (метки по дням ставятся при «день ≥», 0x499610),
  `shop_owl_3` — квест magic_statue, он же даёт `add_owl` (бесплатно +1 уровень, 0x433670). Цены 0 / 100 / 200,
  опыт 10 / 15 / 20. Частиц `root/particles/owl` в resource.xml нет. **Допущение**: сова живёт только днём.
- **Статуи остальных ферм** (`web/src/statue.ts`, общий класс exe 0x4fa680 / 0x4fb590 / 0x4fcad0, эффект — виртуальный
  метод +0x20 вида): цикл как у совы, но после нажатия в покой — на следующем кадре (проверка конца анимации обратная).
  Покупка — метки `shop_<вид>_<уровень+1>`, квест `add_<вид>` даёт бесплатный уровень (loc2 Нептун, loc3 алтарь,
  loc4 горн, loc5 часы).
  - **Нептун** (0x503b00): урон rand(min_damage..max_damage) каждому вредителю, но не насмерть — жизнь не ниже 0.1;
    `prize_k` прибавляется к множителю приза вредителя (+0x100) — призов в порте нет.
  - **Часы** (0x505730, 0x5057d0): замедление `slow_k` вредителей (поле фермы +0x834) на `max_activete_time` секунд,
    снимается и в начале / конце дня. Замедляются анимации и укусы вредителей (0x40f4c8, 0x58e8d0); в порте — весь их
    кадр (dt · slow), день идёт как обычно. `min/max_damage` у часов в данных есть, но эффект их не читает.
  - **Алтарь** (0x4fe7d0): случайный приз из `items` в `position` + случайный сдвиг в пределах `drop_offset`.
  - **Горн** (0x504bc0, 0x504650): round(rand(min_bugs..max_bugs)) вредителей из `bugs` по одному в секунду (первый
    сразу), у каждого множитель приза + `prize_k` горна.

- **Призы из вредителей** (`web/src/prizes.ts`, данные `root/dropped_items`, `farm/prizes_set`):
  - выбор (0x431e40): вес ступени — `prize_k` · множитель вредителя (у пустой ступени — просто `prize_k`), r = rand · сумма;
    из призов ступени — случайный, без тех, чья `difficults` не содержит сложность. У вредителя с `$N` — N гарантированных
    призов из всех ступеней (0x410300). Проверено прогоном: «ничего» 21.4 % при множителе 1 (ожидание 21.7 %).
  - сбор нажатием (0x430370, попадание по пикселям 0x4b54d0): «exp» — опыт, «gold» — золото (в loc5 надпись про
    кристаллы), «water» — вода сколько влезет (0x566a80); надпись «+N …» цветом `float_string_color`. Лежат до конца дня.
  - **Допущение**: место — точка вредителя со сдвигом до клетки (exe ищет свободную клетку сетки в радиусе 3, 0x428870);
    сбор — значок летит к счётчику панели за `effects/prizes time` 0,6 с (ускорение к цели вместо точного интерполятора `interpolator_k` 75, частицы `particles/prizes` не воспроизведены).
- **Модификаторы вредителей** (`parseBugSpec`, разбор 0x401fa0, применение 0x40e0a0): после «!» — `@N` уровень (без него
  модификаторы не действуют), `*k` жизнь, `#k` скорость, `$N` гарантированные призы, `+k` атака; опыт = ⌊опыт · (1 + * / 3
  + # / 3)⌋. Флаг «!» (0x410560) и картинка уровня `@` (0x402040) не разобраны.

- **Серии ударов** (`Farm.comboHit`, `Bug.setComboTarget`, exe 0x430370, 0x410070): попал по вредителю (и по его мишени,
  если она есть) — счётчик фермы + 1 (+0x708), на вредителе новая мишень `bugs/target` в случайной точке
  rand % (2·click_radius − 25) от угла зоны нажатия; попадание в мишень — квадрат 25 × 25 от её угла. Множитель урона —
  `damage` последней строки `combo_set` с ударом подряд ≥ `comobos_count` (×1.2 с 3-го … ×2.75 с 17-го). Мимо мишени —
  серия 0, мишень пропадает. `combo_time` (+0x704) exe только отсчитывает, серию не сбрасывает; сбрасывает начало дня.
  Надписи «Комбо N» / «Урон xM» (bonus_events) — где и каким шрифтом в exe (0x45e1c0 → слушатели), не разобрано.

- **Автосборка букетов** (`web/src/autobouquet.ts`, экран букетов): счётчик фермы (+0x770) — проданные в букетах цветы
  (+ число цветов букета, 0x434078). Пороги `levels_array` идут подряд (80, затем ещё 100; 0x4093f0). Уровень 1 —
  нажатие на свободное место букета переносит туда нужный цветок из корзины (0x510b80); уровень 2 — то же, а если не
  вышло, букет заполняется всем, что есть (0x510da0). Полоса `control` (151; 511): картинка прогресса, обрезанная по доле
  (0x5587a0), значок уровня, на последнем уровне — `complete`; подсказка `tooltips/auto_bouquet_<уровень>` и «нужно
  продать %count%» (0x558250). Цветок при автопереносе перелетает из корзины на место (0x511060) — по дуге за 0,35 с, кривая в exe не разобрана.

## Пятая локация

Панель `stat_control_loc5` с «Кристаллами» вместо «Монет» (`stats/crystals_title`, надпись сжимается по доске) и фон экрана
букетов `bouquets_back_loc5`; приз-валюта уже назывался кристаллами. Окно покупки воды в 5-й локации — тексты `buy_water_loc5`
выгружены, но денег в окне не показывает (у обычного тоже). Картинка кристалла на панели — в самой `stat_control_loc5`.

## Дерево-идол (5-я локация)

`farm/marks_obstacle`: картинка `data/Tree/idol-tree-00…05` 400×150 в (235; 47), по метке `treemark_N`; квесты ставят `treemark_2…6`
(`set_mark`) и `add_vegetation` веток (`blue/green/red/yellow_branch_1`). Показывается картинка последней поставленной метки, она же
препятствие для вредителей и Робина. **Допущение**: `treemark_1` в квестах не ставится — пока ни одной метки нет, виден росток
(`idol-tree-00`). Ветки (`*_branch_N`, картинка `empty`), `idol_tree_flowers` и растение `idol_tree` (жажды нет, плод `p_idol_tree`
15000) — частично. Сделано: грядки с `veg_name` стоят с начала игры (`ridge_10` — дерево-идол, 6–9 — ветки `red/blue/yellow/green_branch_1`,
грядка без картинки `plain`: игрок на неё ничего не сажает, не продаёт и не улучшает); `add_vegetation *_branch_1` сажает ветку на
её грядку; `remove_all_vegetations` их не трогает. Растения идола и веток, плоды `p_*_fruit_N` / `p_idol_tree` и картинки выгружены.
Ветка стадии N считается предметом квеста (`have_items name="green_branch_3"`, окно заданий): считаются растения этого имени на грядках фермы.
Не сделано: `idol_tree_flowers` и особенности `idol_tree` (плод за 15000).

## Перестройка фермы квестами (локации 2–4)

Действия этапов квестов (`store_state` → …), раньше пропускавшиеся: `set_barrels` / `set_boxes` (число уровней), `set_max_barrels` /
`set_max_boxes` (докупать можно только до этого числа), `remove_well` (без `count` — колодца нет, иначе минус столько уровней) /
`add_well` (+1 уровень), `enable_buy_water` (кнопка «Купить воду»), `enable_manual_work` (false — игрок не поливает и не собирает,
только Робин; экзамен в 3-й локации), `set_ridges` (`installed` грядок осталось: из начальных `ridgeCap`, остальное — купленные; докупить
ещё `not_installed`), `update_quest_title` / `change_quest_person` (запись журнала), `add_dragon_medal3` (награда ступени 3).
**Допущения**: смысл `set_ridges`, `enable_manual_work` и `reset_bug_item` (сброс предмета вредителей — предмет забывается) выведен из
данных квестов, в exe эти действия (0x4837bb…) не читались.

## Не сделано

### Сложность
Сделано: экран выбора (`select_difficult_screen`: «Легкий» / «Сложный» и флажок туториала) перед комиксом новой игры;
значения `difficult` (exe 0x425c90, getters 0x4263b0…0x4264b0): покупка ×`buy_price` (0x4b5fb8: цена × умение × k + 0,5 → целое),
продажа ×`sell_price` (0x4b6058), жизнь вредителя ×`bug_life` (0x40eb60), пороги `exp_levels` ×`exp_k` (0x428070; не опыт за действия,
как гласила таблица в DIFF_FROM_MF1), `pour_count` = 1 в обеих и нигде не нужен; призы по `difficults`; раздельные таблицы рекордов.
**Допущения**: у записи волны приставка (`casual-` / `hardcore-`) пропускает вредителя на чужой сложности, без приставки — для любой
(exe 0x419650 строит имя с приставкой, точное правило не разобрано); стандартная таблица рекордов одна на обе сложности.
Жажда Робина (разобрана по exe): срок — случайное целое `round(hunger_min)`…`round(hunger_max)` секунд (0x4c87b0), на **лёгком ×10**
(250–350 с — дольше дня, поэтому там почти не бывает), на сложном как есть (25–35 с). Заводится в начале дня (0x4c75a0) и когда
Робина напоили. Хочет пить, когда осталось меньше половины срока (0x4c7670, флаг +0xe1; ряд капель `progresses/helper_hunger`,
картинка `drop_helper`), на нуле улетает до конца дня (+0xe2). Нажатие по жаждущему Робину (0x430370: попадание по `click_radius`,
0x4c8000) поит его: расходуется вода, срок заводится заново (0x4c80b0); воды нет — событие «нет воды». Нажатие по нежаждущему
Робину (0x4c7fa0 → 0x4c8020, звук `helper_click`) работает как ускорение с остыванием 15 с (подсказка «Клик по Робину увеличивает
его скорость») — **не сделано**: чем именно ускоряется, не разобрано.
Не сделано: квесты `*_hardcore` (`detective_arrive_hardcore`, `explorer_returns_hardcore`, `hardcore_quest`) работают через метки `casual` / `hardcore`
и не проверялись.
